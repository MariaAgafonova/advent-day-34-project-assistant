## Что реализовано

Клиентский React-чат с автоматическими ответами DeepSeek, списком диалогов, историей, источниками, повтором после ошибки и запросом специалиста. API сохраняет сообщение, получает контекст клиента и обращения через MCP SDK/Streamable HTTP, ищет инструкции, вызывает DeepSeek, проверяет JSON и сохраняет ответ со статусом.

Два Cloudflare Workers: публичный Web/API с assets и закрытый CRM MCP, связанный через Service Binding. Общая D1 содержит сессии, клиентов, тикеты, сообщения и отдельный индекс документации. В базе знаний 7 документов / 34 фрагмента. Индексация отдельной командой, повторяемая, с обновлением/удалением документов и стабильными идентификаторами; источники прошлых ответов сохраняются снимками.

Реализованы серверные анонимные сессии, Secure/HttpOnly cookie, проверка Origin, владение тикетами, параметры SQL, ограничения размеров/частоты, таймауты, ограниченные retries, уникальные client_message_id, запрет параллельной генерации одного диалога и защита от записи устаревшего ответа. Сбой MCP/LLM не удаляет пользовательское сообщение.

**Изменение предпочтительного стека согласовано:** используется только DeepSeek API; поиск — реальный D1 FTS5 с расширением запроса DeepSeek. Vectorize и embeddings не используются. Заготовленные ответы есть только в автоматических mock-тестах, в сервисе их нет.

## Ограничения и дальнейшая эксплуатация

- Анонимная cookie не подтверждает личность владельца реального аккаунта; потеря cookie теряет доступ к её обращениям. Нет полноценной авторизации или восстановления аккаунта.
- Статус `needs_human` означает сохранённый запрос. Операторского интерфейса и внешней доставки нет; специалист автоматически не подключается и SLA не обещается.
- Лексический поиск чувствителен к формулировкам. DeepSeek и JSON-валидация не дают гарантии фактической точности или неизменного текста ответа; возможны отклонения от инструкций промпта.
- Редакция email/токенов/числовых кодов перед моделью эвристическая. Исходный текст хранится в D1; перечень передаваемых DeepSeek данных приведён в README.
- Seed-клиенты синтетические и не подменяют сессию посетителя; их обращения не открыты другим клиентам.
- Нет нагрузочных испытаний, мониторинга SLA и автоматической политики удаления старых обращений. API health проверяет конфигурацию/индекс, а не выполняет платный вызов модели.
- На этой Windows-машине для workerd использовались локальные runtime DLL из установленного Python/NumPy. Они не входят в Git. После чистого `npm ci` может потребоваться обновить Microsoft VC Runtime x64 либо использовать Linux/CI; опубликованный Worker от этого не зависит.

Для демонстрации дополнительных шагов не требуется: открыть опубликованный URL и задать вопрос. Для изменения документации — `npm run index -- --remote`; для изменения Web/API — `npm run deploy:web`; для CRM — `npm run deploy:mcp`. Базу заново не создавать. Операторский интерфейс, полноценная авторизация и эксплуатационные механизмы — отдельные будущие задачи.
